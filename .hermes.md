# Scrum Ceremony Platform — Hermes Guardrails

## Architecture Constraints (NEVER VIOLATE)

### Data Boundaries
- Product PostgreSQL owns: ceremonies, boards, votes, actions, analytics, AI outputs
- ERPNext MariaDB owns: leads, contacts, customers, invoices, sales orders
- NEVER cross-query between databases. Use the integration service.

### Anonymity Hard Rules
- Anonymous notes MUST store author_id in a SEPARATE table from display content
- The `board_items` table NEVER contains user_id when anonymity is active
- NEVER log or expose anonymous author identity in API responses
- Vibe-coded code that touches anonymity MUST be human-reviewed before merge

### State Machine Rules
- Ceremony state transitions are defined in ceremony FSM specs
- NEVER allow Hermes to modify FSM definitions without explicit approval
- Every state transition MUST be tested: valid transitions pass, invalid fail

### CRDT Rules
- Board sync uses Yjs ONLY. No custom conflict resolution.
- NEVER modify Yjs internals or binding adapters without review
- CRDT test suite must pass: concurrent edits, reconnect, offline

### Multi-tenancy
- EVERY database query MUST include tenant_id filter
- Row-level security is enabled on ALL tables
- NEVER write a raw SQL query without tenant_id WHERE clause

### AI Rules
- ALL AI outputs marked "suggested" until facilitator approves
- Gemma 9B outputs validated against JSON schema before storage
- NEVER allow AI to directly create Jira tickets or modify action status
- AI service has no write path to Jira

### Integration Rules
- Jira sync operations are idempotent (idempotency key on every request)
- ERPNext sync failures go to dead-letter queue, never silently dropped
- Stripe webhook signatures ALWAYS verified before processing
